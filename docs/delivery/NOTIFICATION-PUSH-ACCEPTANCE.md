## Dedicated forwarding policy

`server/inbox-stream.mjs` is reached through the existing session boundary before finite-response capacity/deadline/body policies. Ordinary request protections remain intact. Tokens stay server-side; query strings on the stream route are rejected. Last-Event-ID accepts URL-safe values up to 256 characters. Header acquisition has a 15-second deadline which clears once headers arrive; it is not a whole-stream deadline.

The single-process pilot policy admits two streams per local session and one hundred globally, separately from ordinary request admission. It bounds each chunk to 64 KiB, each framed event to 4 KiB, and a connection to 1,024 frames including comments. There is no cumulative finite-body cap. The browser owner opens only one connection. Heartbeat comments reset the 45-second idle timer. Connection lifetime is bounded by 310 seconds and the local session/access-token expiry. A downstream stall closes after five seconds; pull-based forwarding and Node pipeline backpressure bound queued memory. HTTP headers flush before the first event. Browser disconnect, cancellation, logout, refresh failure and session expiry cancel upstream work and release admission once.

The backend retains its own 15-second heartbeat/auth checks, 60-second resync and approximately 290-second rotation plus recipient/global Redis admission. This frontend policy does not promise cross-process session sharing. D06 restart/signout and production HTTPS topology acceptance remain separate.
