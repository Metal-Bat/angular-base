## Boundary limits and operations

API body/header/body-transfer phases use deadlines: ordinary phases 15 seconds; `/api/v1/media/` and `/api/v1/reports/` proxy phases use `BOUNDARY_TRANSFER_TIMEOUT_MS` (default 60 seconds, configurable 15–300 seconds). These are phase deadlines, not a measured end-to-end SLO.

`BOUNDARY_MAX_IN_FLIGHT_REQUESTS` defaults to 8 (1–32). It bounds proxy body-reading and upstream-header work without queuing another buffered command. Capacity rejection occurs before dispatch and reports `uncertain:false`. Streaming downloads use backpressure after header work releases capacity; active socket/stream memory still needs measurement at the agreed concurrent profile. Upload memory includes bounded parts and the concatenated body; this is not a fully streamed upload implementation. Avoid increasing limits without measuring the deployment profile.
