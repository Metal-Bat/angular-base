# Process, task and Calendar continuation

2026-10-17. Existing ownership: APP-FE-032.UX01, APP-FE-028.UX04, APP-FE-029.UX02/03/04 and APP-FE-014.UX01; master V32–V35. This is a continuation of the current implementation, not a new process engine, scheduler, permission model or calendar library. Parent/master status remains partial where producer or manual acceptance is outstanding.

## Repaired behavior

- Process tracking observes route changes instead of retaining the first process forever. Superseded reads are aborted/fenced. Refresh retains the confirmed timeline page and uses the current returned reference. Transient outages retain the current view; denied/missing records clear it. Recovery drafts guard route changes and pause automatic tracking refresh. Status, refresh and parent navigation share the header; current positions are a readable table and timeline instants use localized date/time with exact instants available on demand.
- Real-service task commands now retain the owning task `ref_id` when the DTO also carries a parent `request_ref_id`. Runtime/attachment wrappers still use their explicit owning references. The browser fixture includes both fields, matching the producer shape that exposed the defect.
- Human task decisions remain the producer-declared actions in the task action area above the activity/pin summaries. Supplemental commands now use the same area and a compact menu. Comments and forwarding open focused dialogs, preserve unconfirmed input, guard dismissal/navigation, restore focus, and clear private drafts on actor change. Personal read/pin/watch/archive menu entries use actual actor-specific timestamps; acknowledged changes refresh their current projection. Terminal tasks do not offer lifecycle closing. The existing cancel/expire confirmations remain available in a focused lifecycle dialog.
- Forwarding uses the existing paginated, authorized recipient picker instead of copied user/group references. A recipient and reason are required. Confirmation still precedes the unchanged operation-specific command. A confirmed handoff clears the sender's editor and returns to the inbox without trying to load the recipient's form. Cancelled/failed/uncertain commands retain their established queue and recovery semantics. AI approvals cannot be forwarded.
- AI tool approval parameters reuse the structured field-value presenter, including nested values, zero, false and null, instead of a JSON dump. The dedicated approval endpoint, exact approved boolean, command key, expiry checks and required human business decision remain separate.
- Worker retry is offered only for a recorded FAILURE; revoke is offered for pending/running delivery states. Known impossible simple process transitions are excluded. Availability is rechecked after confirmation. Missing inspection state does not broaden recovery-only operators or fabricate a process GET. Operation-specific APIs and server authorization remain authoritative; accepted/queued work is not shown as completed.
- The Calendar settings date picker applies each valid selection immediately; incomplete or cleared input does not request an invalid period. The mini-calendar and picker share the displayed anchor. Month cells and Week/Day headings visibly mark the selected date independently of today, with localized accessible date labels. Regression coverage selects actual dates through both controls in English/Persian at phone width. Timezone changes retain their explicit Apply control and are not submitted by date navigation. Reviewed Persian phone captures exposed overlapping weekday names in the shared popup; its seven-column header now uses localized narrow labels, while date buttons retain full accessible dates. A browser check verifies that header text fits its cells. Desktop view buttons now use a filled primary treatment for the selected period, matching their existing pressed state, rather than rendering all four as identical outlines.
- Calendar Week and Month selections bring the chosen date into the component's own horizontal scroller. The time column remains pinned in Week/Day; overflowing grids have keyboard focus, names and a localized scrolling hint. Alignment handles RTL and resize without scrolling the outer page. Existing view/source/temporal choices and event identities are retained.
- Calendar selection has a separate generation fence: an earlier slow detail/reminder response cannot replace a later event, Create, Close or period selection. Same-page event query changes are observed and dirty drafts require confirmation. Manual and work-item editors receive deliberate focus. Editor deletion now uses the same current-authority read, confirmation and uncertain-result fence as popover deletion.

## Contract and migration boundaries

No endpoint, DTO, generated client, migration, shared data, published version or active pin is changed. Inspected producer sources include work-item `dto.py`/`service.py`, task execution routes, process state/service/compensation policy and the frozen OpenAPI. Worker task_id remains distinct from revision ref_id. Process current positions and operation-specific recovery still determine whether more complex commands are actually permitted; the presentation guard does not promise every state-compatible command can execute.

The recipient picker public seam and Operations route composition are documented in [UI-LIBRARIES.md](../UI-LIBRARIES.md). The existing admin user/group selectors require their respective directory-management permissions. An ordinary reviewer without them gets safe denial and no copied-ID workaround. A bounded forwarding-context recipient selector is an exact producer gap; no broader reviewer grant is added. Existing process discovery and readable business identity gaps also remain.

Calendar active reminder configuration and eligible team selection remain producer gaps. This continuation does not enable drag/resize that could erase reminders, infer active offsets from delivery history, or permit derived deadline editing. The owner's BPMN if/else seed correction remains backend-owned.
