# APP-FE-016 / APP-FE-020 / APP-FE-021 — Editor flow audit and repairs

Date: 2026-10-18. Status: IMPLEMENTED. The scoped final verification status is recorded in `artifacts/editor-flow-audit/completion.json`; absence of a successful receipt means verification is incomplete. This scoped follow-up does not close the APP parents or the master backlog.

The reported broken form and canvas workflows were reproduced through native Firefox against the running backend. The earlier minimal API-created-draft checks did not establish complete UI authoring acceptance. This audit creates disposable roots and drafts through the visible catalog controls, retains failed attempts, and checks actual save/reopen behavior separately from the fixture suite.

## Reproduced problems and changes

- The form palette installed an expression calculation inside repeated items, which the backend rejects with `behavior.expression_repeated`. Repeated calculations now remain pending until the author selects a registered function and real source fields. Apply and Save are fenced while incomplete; Cancel restores the previous document. Redo restores the pending fence too. Repeated-item expression editing is unavailable because the producer does not support it.
- Selecting Sum left the calculated result's canonical schema as text. The editor now validates source types and collection context, exposes the result type, and applies a compatible result schema atomically with field properties. Compatible numeric schemas, nullable result policy, unrelated metadata and override policy are preserved. Incompatible sources and direct self-dependencies remain local errors. Server validation remains authoritative, including transitive dependency checks.
- Expected preview validation became an unhelpful unavailable message, while the global error toast covered Save and Validate. Safe issue pointers/codes now reach Diagnostics from the preview; global error feedback remains available at the bottom of the screen, including support/correlation controls. The relocated toast uses an opaque semantic surface after the full accessibility gate exposed a dark-theme contrast failure. Nothing suppresses service failures or diagnostics.
- Multiple-choice presentation could emit an array while the canonical schema remained scalar. The Multiple control now wraps/unwraps the scalar item schema with typed constraints and defaults, retaining unrelated metadata and nullable policy. Custom numeric/boolean keys align the scalar/item schema when needed; incompatible existing constraints remain local errors. Compatible preview samples convert between single and multiple values, including nested rows; incompatible multi-value samples are cleared with an explicit notice rather than silently choosing one value. Lossy multi-value defaults are rejected. Authoring option reads have an explicit immutable definition identity, allowing a deliberate definition edit to reset option lookup without disabling unexplained revision/fingerprint checks during pagination or for published runtime ports. Nullable array choices also render a real multiselect without requiring a duplicate presentation flag. Preview HTTP success alone was not accepted as schema/value conformance.
- Applying ordinary field properties reset the active inspector accordion to General. Selection defaults now preserve the active group for the same stable field identity, reset for another field, and still open Behavior when a calculation needs configuration. The reset was reproduced in native Firefox against the real backend, in addition to both regression engines. The medium-width preview driver now explicitly closes Tools before checking the adjacent preview; answer, label and save/reopen assertions remain intact.
- The complete 320-case collection run exposed a Firefox filter chooser race: the 500 ms startup poll changed controls to disabled between pointer-down and click. Ten unchanged replays reproduced it once; trace snapshots show both field and operator becoming disabled. Request/task automatic polling and notification refreshes now pause while Advanced filters is open; notification revisions coalesce and resume on close. Explicit Refresh/Apply and their loading fences remain intact. This repairs the owner refresh policy rather than altering select geometry or retrying the click.
- A subsequent complete run reached 323/324 and exposed an intermittent Firefox Calendar Cancel miss. The trace shows scroll position changing from 121 px to zero during the gesture: the editor mounted before the leaving event-details popover stopped contributing overflow. A MutationObserver assertion reproduced that overlap deterministically against the old build. Edit now waits for the installed Popover's public onHide completion before opening the editor; explicit close, replacement details, busy state, actor change and destruction fence pending edits. Trigger focus uses preventScroll during the transition. Existing Cancel, current-reference deletion and keyboard focus assertions remain, with the no-overlap invariant added.
- Undo and Redo appeared enabled without history. Their availability now follows actual form history.
- Four live built-in node schemas carried root `x-step-definition` and `x-step-definition-fingerprint` annotations. Their unchanged configuration schemas were rejected, disabling typed settings for AI Decision, Connection Status, Permission Check and Request Priority. Only these two root annotations are separated when the fingerprint matches the frozen handler contract. Other annotations, unknown fingerprints and actual schema changes still fail the strict comparison. No producer schema, generated registry, pin or transport contract is changed.
- Selecting a palette item in a narrow workflow editor left its placement destination hidden behind Tools. Selection now reveals the mounted canvas; adding a step reveals the result and centers the new step at the current zoom for button-based additions. Explicit pointer placement retains its coordinates. An intermediate automatic-fit implementation shrank the diagram and caused port overlap after undo; that failed attempt is retained. Centering preserves the chosen zoom; Fit remains an explicit navigation command. Inspector padding is reduced without shrinking controls.
- At low overview zoom, inverse-scaled accessible sockets extended beyond shrunken cards and covered a neighboring input. Socket attachment offsets now cap their outward extension while retaining physical target size; the original fitted-scale reachability assertions remain required. The final accessibility pass also exposed shrunken selection-button targets; their minimum physical height now follows the socket scale, and Fit includes that nonlinear height.
- The form editor squeezed three panes below the master's useful width. Three panes now require approximately 1240 pixels of available container width. Medium containers keep design and preview; Tools temporarily occupies the preview area. Below 960 pixels, tools use the bounded split panel and Preview remains a separate mode. State is shared across these presentations. Named Add field and Add step actions expose authoring directly, including when the tools dock is collapsed. Scroll anchoring is disabled on the actual editor scroll containers to prevent Firefox's repeated anchoring adjustments during dynamic updates.
