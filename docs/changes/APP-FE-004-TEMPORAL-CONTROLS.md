# APP-FE-004 — Shared temporal controls and responsive tables

Date: 2026-10-11. User-requested continuation of existing shared UI ownership; affected consumers retain APP-FE-007/008/014/015/017. Implementation: implemented. Verification evidence: complete final gate artifacts referenced below; no integrated/deployed/user-readiness claim.

## Result and reuse

The reported datetime table filter was a plain text input with an ISO placeholder. Shared TemporalControl now replaces it and date inputs in column/advanced filters (including both range endpoints and every membership value), schema-based Administration/Studio editors, supported runtime date/datetime primitives, calendar event/date editors and dashboard ranges. It uses the installed PrimeNG 21.1.10 with the existing theme/palette/dark mode, shared selection and field wrappers. No dependency or framework change.

English uses Gregorian, Farsi Jalali and Arabic civil/tabular Hijri. Every date picker allows an actor-scoped session override shared by other pickers and date presenters. Switching calendars/languages preserves canonical values and invalid drafts. Logout clears calendar choice, popup state and temporal buffers. Dates stay Gregorian ISO; instant edits produce UTC timestamps in the configured IANA zone; local event minutes retain the existing event offset-choice semantics. Gaps fail and folds require explicit choice. Original fractional instants are not normalized by display/calendar changes. Invalid edited strings cannot reuse a stale valid instant and are rejected by the existing caller validation. Time-only values use PrimeNG's clock picker; no unsupported runtime component kind was added.

The calendar grid is a documented scoped exception to using DatePicker for date arithmetic: pinned PrimeNG implements Gregorian arithmetic, whereas Intl supports Persian and civil Hijri. Actual selected-calendar month lengths and conversion are used, with labelled PrimeNG day buttons, arrow-key movement, focus-contained PrimeNG dialogs and explicit close labels. DatePicker spinner labels in this pinned version land on p-button hosts; supported nested passthrough forwards them to native buttons without dependency changes. Calendar views use matching month boundaries; the live calendar search retains the existing authorized endpoint and a bounded union of the three presentation windows.

Tables lose the 80rem console-page limit and small-density override, expand to available width and give data cells readable minimum widths. Long content stays complete, wraps, and wide tables scroll inside their existing PrimeNG viewport. Shell/sidebar responsiveness and purpose-specific editor/modal bounds remain intact.
