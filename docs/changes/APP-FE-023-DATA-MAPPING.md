# APP-FE-023 — Data mapper continuation

Date: 2026-10-18. Owner: APP-FE-023. Parent status remains BLOCKED; implementation, browser integration, execution and product acceptance are distinct.

## Behavior and reused owners

The existing graph mapper now exposes all input cardinalities rather than discarding LIST and structured ports. Designers add and edit scalar, object, array and nullable constants through fields. Explicit empty text remains distinct from omitted input and is checked against its actual string constraints. Arbitrary payload/default keys remain ordinary data fields rather than inheriting fixed-DTO reference-picker heuristics; fixed configuration selectors and declared recipient references remain governed by their existing controls. Shared schema controls now opt into literal-value semantics only for mapping constants and transform defaults: nested empty strings stay values, while ordinary form-required checks retain their established behavior. Union controls reopen object/array branches correctly, initialize primitive branches with the matching value shape, and preserve decimal numbers. Unsafe integer literals require text plus an explicit integer conversion rather than silently losing precision. Reference-valued recipient collections use the existing authorized user selector and current-resource resolution; they do not require copied IDs. LIST chunks can be appended, reordered and removed, keeping dense ordinals local to one input. Editing retains unrelated binding metadata. Mapping changes preserve control edges; authored data routes and selection follow their bindings through edits and ordinal changes.

Authorized completion remains the source boundary. The current draft dominators still exclude outputs that can be bypassed. Nested request properties, whole collections, explicit zero-based collection indexes and fields inside collection items produce escaped canonical JSON pointers. Invalid indexes/fields and incompatible types retain the input buffer and leave the graph unchanged. Mapping edits wait for catalog-backed input definitions; obsolete bindings can still be deliberately removed without JSON. Recipient selection resets after each add so the same authorized choice works again, with keyboard focus returned to the new search field. Clearing an existing recipient removes its stored value; pending selection blocks competing row changes. Temporarily disabling the panel preserves its buffer; actor change and teardown clear private editor state and reject late completion results.

Transform v2 ports now use the exact configured producer input/output schemas rather than the generic registry schema. Explicit conversions compose through existing steps and data ports; conversions are not silently inserted into the control graph. Structured object projection uses source-field choices and named destination fields, including nested fields from declared inputs or synthetic constants. Incomplete projection rows fence Apply. Required defaults, unsupported formats and incompatible projection/conversion combinations produce local errors; actual server validation remains authoritative.

Normal mapping controls use shared PrimeNG controls, the existing SchemaInput public seam and existing StudioChoice authorization/current-reference behavior. Foblex remains the tested direct-port drag exception. English, Persian and Arabic messages are frontend-owned. Mapping source kinds and schema summaries use localized display labels while canonical values remain unchanged. Legacy nested prior-output bindings show the explicit backend-runtime repair warning. No package, public DTO, route, seed, migration, backend source, shared database reset or vendor operation changes.

## Reconciled producer limits and peer handoff

Read the actual GraphBinding DTO, workflow service validation, GraphValidator, process input assembly, completion producer and transform_schemas implementation. Reconciled recorded DB-002/D07 decisions; no schema policy or exception changed.

1. **Nested STEP_OUTPUT execution mismatch (APP-BE-019 / process runtime):** validation projects `source_path` through `source_schema`, but `ProcessService._step_output` returns `execution.output_snapshot[port.port_key]` without applying that path. The direct mapper therefore does not offer nested prior-output extraction as executable. Fix and verify the runtime contract before enabling it; preserve the exact pinned root output schema.
2. **Combining unrelated sources into one object destination:** GraphBinding has no target-field path or object assembly contract; SCALAR permits one binding. Supported single-object Transform projections and structured constants are available. Arbitrary cross-source nested destination composition requires a producer decision, rather than inventing `target_path` or a frontend execution engine.
3. **Private sample previews:** no approved authorized/redacted execution-sample projection is consumed by this owner. The mapper does not fetch full private execution snapshots. Constant-derived field inventory is based only on the designer's entered values and is not real execution preview.
4. **Published LIST notification execution:** recipient WIP authoring does not verify a notification provider or authorize dispatch. Actual provider delivery is separate from mapping acceptance.

These limits keep full APP-FE-023 parent closure blocked; they do not hide supported LIST, nested request, constants, conversion or projection controls behind JSON. Existing published graphs, active pins and request/form data remain untouched.
