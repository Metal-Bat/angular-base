# APP-FE-004 — Calendar cell tracking repair

Date: 2026-10-11. Continuation of the shared temporal controls; no parent feature readiness or live-backend acceptance claim.

The user reported `NG0956` in the temporal DST and local-minute tests, failing the strict `mise run check` diagnostic gate. The grid tracked each date string by identity. Moving to a disjoint month could recreate every button, rather than update the existing month-day cells.

The grid now tracks its ordered month-day positions by `$index`. These positions are contiguous, with changes in month length confined to the end of the collection. Button labels, canonical dates, selection state and click/keyboard bindings still update for the displayed month. This repairs actual DOM reuse without filtering diagnostics or changing the warning gate. Calendar conversion, timezone/DST semantics, published contracts and preferences are unchanged.

The regression test opens the actual PrimeNG date dialog, moves from March to May before rendering (two disjoint 31-day months), checks reuse of all 31 native buttons, moves to April and checks reuse of its 30 cells, then clicks a reused button and verifies the updated canonical date. The unmodified seven-test focused run passed without reproducing the user's warning (`/tmp/temporal-tracking-before.log`). Adding this deterministic regression reproduced both `NG0956` and failed DOM-identity assertions before the repair (`/tmp/temporal-tracking-regression-before.log`). After the repair, all eight focused tests passed without stderr/warnings (`/tmp/temporal-tracking-after.log`). No assertions or diagnostics were suppressed.

Delivery inventory was refreshed after the template change (`/tmp/temporal-tracking-inventory.log`). AST-only graph refresh is recorded in `/tmp/temporal-tracking-graph.log`. Complete final verification is recorded in `/tmp/temporal-tracking-check.log` and `artifacts/check/manifest.json`: the latter retains command exits, diagnostic counts and start/end source hashes. The preceding manifest is retained at `/tmp/temporal-tracking-pre-check-manifest.json`; previous temporal evidence remains historical. Completion is determined by the actual complete gate result, not the focused test alone. Browser runs use isolated local fixtures and do not establish deployment or user acceptance.

The first complete gate passed 595 unit tests, build and earlier browser scopes, then timed out in the existing records report-password accessibility check (`/tmp/temporal-tracking-check-failed-1.log`, manifest retained separately). Its palette loop had a fixed 350ms delay followed by the accessibility helper's 400ms settling delay for every palette/mode. The existing accessibility audit now supplies that settling period before the same palette assertions; the redundant 350ms wait is removed. All fourteen palette audits, computed-color assertions, diagnostics and the original 45-second browser deadline are retained. The complete gate is rerun, with final result in the log/manifest above.
