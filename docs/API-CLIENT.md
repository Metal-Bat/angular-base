# Typed API transport and authentication

Steps 9–13 are implemented locally against the reviewed platform contract. Steps 19–23 now consume this transport from the shared renderer and requester/reviewer screens. Browser evidence uses real Angular and Firefox with a disposable protocol fixture; deployment, reverse proxy configuration and live backend account verification remain integration gates.

## Generation

`npm run api:generate` generates the schema and operation catalog from `docs/reference/platform-openapi.json` using pinned `openapi-typescript@7.13.0`. `docs/reference/client-generation.json` records the input SHA256 and settings. `npm run api:check` verifies the original inventory, platform manifest and exact generated bytes. CI fails on missing or changed generated output. Generated files are excluded from formatting/lint rewriting and checked by TypeScript instead.

The generator preserves snake_case, nullable properties, selector unions and opaque references. Binary schemas expressed as `format: binary` or `contentMediaType: application/octet-stream` become `Blob`. Compile fixtures cover these properties. Generated types describe the wire contract; they do not validate dynamic render documents. [Step 18](RUNTIME-DOCUMENT.md) provides the validated model; [Steps 19–21](RUNTIME-RENDERER.md) supply the renderer and conformance coverage.

`ApiClient.call(operationId, input)` supplies typed parameters, bodies and success responses for exact `/api/v1` operations. `ApiClient.domain(tag).call(...)` restricts operations to the selected contract tag and checks the tag at runtime. The operation catalog loads lazily. Whole opaque path parameters are percent-encoded; query values use URLSearchParams. Multipart requests use FormData without manually setting a boundary. `HealthClient` separately addresses `/health` and `/ready`; internal service routes are excluded from its interface. Browser login/refresh/token operations remain blocked by the boundary even though their schemas are generated.

## Responses

Use the adapter matching the endpoint: `readData`, `readResultPage`, `readDataPage` (including process scheduled actions), or `readSelector` for bounded bare arrays. `readBareToken` verifies the OAuth contract for fixtures; browser authentication consumes the session-boundary contract instead. Decoders validate the projected values. Page indexes start at one, sizes are bounded to 100 and malformed pages fail.

The original HttpResponse remains available. `responseMetadata` retains HTTP status, application code and correlation ID separately, including HTTP 200/application 204. `ApiFailure` preserves status, application code, request ID and safe pointer/code issues from `data.issues`. Proxy markup, raw invalid inputs and private response values are not displayed or logged. Unknown mutation outcomes require an authorized read and user reconciliation; transport has no automatic command retry. Step 25 implements private download/upload progress, cancellation, safe filenames and object URL cleanup; see [operations services](OPERATIONS-SERVICES.md).

## Session and access

The initializer reads `/session/status`, verifies `/api/v1/auth/me`, then loads every permission page before resolving authenticated state. Service failure leaves access unresolved. Signed-out protected routes go to `/login` with a validated local return path; missing capabilities go to `/forbidden`. External, traversal and control-character targets are rejected. Login distinguishes incorrect credentials, forbidden account/client release and service failure, and clears the password afterward.

Capabilities are the actual backend permission keys, including `admin.users.manage`, `admin.permissions.manage`, `admin.work_groups.manage`, `admin.tasks.manage`, `admin.history.read`, `integrations.manage` and `processes.recover` for the current administration entry policy. Operations requires `requests.start`; Studio accepts `forms.manage`, `workflows.manage` or `requests.manage`. The server's explicit `*` permission is honored. No superuser status, group membership or role name is converted into a permission locally. Every later private child route must declare its exact mandatory/alternative capabilities.

Navigation follows current capabilities. Window focus and authoritative API denials revalidate permissions; revocation clears actor memory and redirects a denied open route. The shared task-affordance helper accepts current server actions and additionally requires a current claimant, active lifecycle and edit purpose. Observer, summary, print, closed and non-claimant contexts expose no completion actions. Product task controls will consume this policy in their own later steps.

Logout clears memory and aborts protected work before contacting the boundary. Bootstrap/login responses are fenced by generation so late responses cannot restore the previous actor. BroadcastChannel carries only `changed`/`logout` notifications, never credentials or actor documents, and closes with its owner. Other tabs immediately clear access on logout and re-bootstrap on account changes. No browser storage is introduced.

## Local verification

`mise run check` runs deterministic contract checks, types, lint, Angular tests, boundary races and the production build. With Firefox installed, run `npm run test:browser-boundary` and `npm run test:browser-auth` after building. The latter exercises the built Angular login UI, invalid credentials, reload, page-two permissions, denied administration navigation, revocation while open, cross-tab logout, family expiry, return-path safety and empty storage. See [SESSION-BOUNDARY.md](SESSION-BOUNDARY.md) for renewal behavior and deployment limitations.

Step 17 adds [shared mutation coordination](COMMAND-COORDINATION.md), including explicit safe conflict categories and reconciliation. Steps 14–16 add the [UI foundation](UI-FOUNDATION.md); `npm run test:browser-ui` builds and tests its development fixture.
